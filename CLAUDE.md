# CLAUDE.md — IQS Flutter: Self-Instructions (read every session, follow exactly)

> This is the **governing rules file** for wiring the IQS Flutter app to its Laravel backend.
> The canonical build sequence is [FLUTTER_BUILD_PLAN.md](FLUTTER_BUILD_PLAN.md). **This file = the rules; the plan = the steps.** When they ever disagree, the plan wins on *what to build*, this file wins on *how to behave*.

---

## 0. Mission (one sentence)

Take the existing, finished **Claymorphism UI** and make it show **real data from the IQS Laravel API** — without redesigning a single screen. Add the data/state/network/routing/i18n layers underneath the UI, and add **new screens only where the plan calls for them**, built from the **same** clay kit so they look native.

---

## 1. The four inviolable rules

### Rule 1 — The UI does not change. Ever. (Highest priority.)
- **Do not** alter layout, spacing, padding, radii, colors, gradients, shadows, fonts, font weights, sizes, icon choices, RTL child-ordering, animations, or copy of any **existing** screen or widget.
- The theme files are **frozen design tokens** — treat as read-only unless explicitly told otherwise:
  - [lib/theme/app_colors.dart](lib/theme/app_colors.dart) (`AppColors`)
  - [lib/theme/app_text_styles.dart](lib/theme/app_text_styles.dart) (`AppText`)
  - [lib/theme/clay.dart](lib/theme/clay.dart) (`Clay`)
- The clay widget kit in [lib/widgets/](lib/widgets/) is **frozen** — reuse it, never restyle it. Allowed kit: `ClayCard`, `Clay3DButton`, `ClayOutlineButton`, `ClaySocialButton`, `ClayCircleBadge`, `ClayHeaderButton`, `SettingsIconTile`, `ClaySectionTile`, `ClayToggle`, `AppHeader`, `BottomNavBar`, `NetworkImageBox`, `Pressable`.
- The **only** edit allowed inside an existing screen is **swapping its data source** — replace a hardcoded `static const` list / `picsum.photos` URL / placeholder string with values that come from a provider/model. The widget tree, styling, and structure stay byte-for-byte the same.
- If wiring real data seems to *require* a visual change, **STOP and ask** — do not improvise a redesign.

> Two sanctioned, **visually-invisible** infrastructure swaps the plan mandates (allowed because the pixels are identical):
> - `google_fonts` Tajawal → **bundled** Tajawal asset, keeping `AppText`'s API and output identical (plan §1.1).
> - `NetworkImageBox` internals → `cached_network_image`, **behind the same API/look** (plan §1.3 "reconciliation").
> Anything beyond these two is a UI change and is forbidden without explicit approval.

### Rule 2 — Always work to the plan, phase by phase.
- Follow [FLUTTER_BUILD_PLAN.md](FLUTTER_BUILD_PLAN.md) **in order**. Phase 1 (Foundation + Auth) is a prerequisite for everything; do not wire feature screens before the `core/` foundation exists.
- Do not skip ahead, batch unrelated phases, or invent scope not in the plan. One phase at a time; each ends **green** (see §6 Definition of Done).
- Resolve the relevant **Open Decision** (plan §5, items A–G) *before* starting the phase it affects. Confirmed decisions get recorded in §8 of this file.

### Rule 3 — Real data only; no fake data left behind.
- Every `TODO(content)`, `static const _slides/_news/_today/_tomorrow/...`, and `https://picsum.photos/...` URL must be replaced by data fetched through the API client.
- Never hardcode domain data that the backend owns. Never ship a screen still showing placeholder content for a feature whose endpoint exists.
- Images are **relative storage paths** from the API — always render them through the `assetUrl(...)` helper (`{STORAGE_BASE}/storage/<path>`), never raw.

### Rule 4 — New screens are allowed, but must look like they already shipped.
- The mockups cover ~5 screens; the plan adds many (auth/OTP/register, match detail tabs, listing detail, club/fan-group profiles, payments, notifications, settings, etc.). Build these **when the plan reaches them**.
- New screens **must** be assembled from the existing clay kit + theme tokens (`AppHeader`, `ClayCard`, `Clay3DButton`, `AppColors`, `AppText`, `Clay`). No new colors, no new font, no new shadow language. They should be indistinguishable in style from the original five.
- Reuse the documented chrome the plan points at (e.g. the `NewsScreen` header/tab styling for club profiles, the `_buildMatchCard` design for fixtures, the More-screen settings-row pattern for settings).

- All hosts live in `lib/core/config/env.dart` as the single source of truth (`Env.apiBase`/`Env.storageBase`, resolved per `FLAVOR`). Changing the host is a one-line edit there.
- ✅ **Live verified (2026-06-24):** `GET https://apifootball.teknoiq.com/api/v1/app/config` → **HTTP 200** with the same `{success,message,data:{version,settings}}` envelope (HTTPS + `/api/v1` path + same Laravel app confirmed). `version.latest=1.2.0`, `min_supported=1.0.0` (app `appVersion=1.0.0` ≥ min → no force-update lockout).
- ✅ **Port verified (2026-06-22):** the API answers on `:8000` — `GET http://127.0.0.1:8000/api/v1/app/config` → `HTTP 200` with the `{success,message,data:{version,settings}}` envelope. Port 80 is closed.
- ⚠️ **LAN reachability:** the LAN IP `http://192.168.0.188:8000` was **not** reachable in testing, because Laravel's `php artisan serve` binds to `127.0.0.1` by default. For a physical device to hit the API, start it with `php artisan serve --host=0.0.0.0 --port=8000` (and allow port 8000 through the Windows firewall). The Android **emulator** instead reaches the host via `http://10.0.2.2:8000`.
- Demo login for acceptance testing: phone `+9647700000001`; with `OTP_EXPOSE_CODE=true` the OTP response returns `debug_otp`.

### Verified live-API facts (probed 2026-06-22 against `127.0.0.1:8000`)
- **`Accept: application/json` is mandatory on every request.** Without it, a protected endpoint returns **HTTP 500 `"Route [login] not defined."`** (Laravel redirects unauthenticated browser requests to a non-existent `login` route). **With** it, the same call returns a clean **401 `"Unauthenticated."`**. The Dio client sets this header by default — never remove it.
- `request-otp` body `{phone}` → `data:{phone(masked), expires_at, expires_in:300, debug_otp?}`.
- `verify-otp` body `{phone, otp}` (field is **`otp`**) → `data:{token, token_type:"Bearer", user{…}, is_new, needs_registration}`. Wrong code → **422** `errors:{otp:[…]}`.
- `User` JSON keys: `id, phone, name, email, avatar, governorate(String), gender, date_of_birth, locale, supported_club_id, supported_team_id, phone_verified, is_registration_completed, roles[], created_at`.
- `governorates` → `[{code, name}]`. `pages/:slug` → `{slug, title, content, updated_at}`. `app/config` → `{version{latest,min_supported,update_available,force_update,store_url,changelog}, settings{…dotted.keys}}`.
- **Laravel `decimal:N` casts serialize to JSON _strings_, not numbers** (e.g. club `latitude`/`longitude` arrive as `"33.3152000"`). Parse any decimal-cast field defensively (`v is num ? v.toDouble() : double.tryParse(v.toString())`) — a strict `as num` cast throws and kills the whole screen. **Watch this in Phase 7 (payment `amount`).**

### Backend contract (applies to every call) — from plan §0
- **Success envelope** `{ success, message, data, meta? }` → **always unwrap `data`**.
- **Error envelope** `{ success:false, message, errors? }` → `errors` present only on **422**. Map 422 `errors` to form fields; show `message` for business 403/404/422; back off on **429** (respect `Retry-After`); on **401** clear token → `/welcome`.
- **Pagination** `meta.pagination = { current_page, per_page, total, last_page }` (exactly 4 keys). `hasMore = current_page < last_page`. `per_page` default 20, max 50.
- **Reads** are pre-localized by the server (one language per field). **Writes** still send raw `_ar/_en` columns.
- **Role gating is ownership-driven, not role-string.** Gate manage-* UI by **probing the endpoint** (200 vs 403, or `my-store ≠ null`), per plan §0 role table. `user.roles[]` only decides whether to *show* an entry point.

## 3. Architecture to follow (plan §1 — non-negotiable stack)

- **State:** `flutter_riverpod` (+ `riverpod_annotation`/generator). Wrap all async in `AsyncValue`.
- **Network:** `dio` with 4 interceptors — Auth (Bearer + 401 handling), Locale (`Accept-Language`), Error (envelope → typed `ApiException`), Log (debug only). Widgets **never** touch Dio directly — always go through the `core` `ApiClient`.
- **Routing:** `go_router` with a `ShellRoute` for the 5 bottom-nav tabs (replaces the manual `IndexedStack`/callback navigation in [lib/screens/main_scaffold.dart](lib/screens/main_scaffold.dart)), detail routes pushed above the shell, an auth `redirect` guard, and the shared `action_type`/`action_value` **deep-link router** (built in P1, reused by banners P3 + notifications P8).
- **Folders:** feature-first under `lib/features/<feature>/` each split **data → application → presentation**; shared foundation under `lib/core/` and `lib/shared/`. Keep existing `lib/theme/` and `lib/widgets/` where they are. (See plan §1.2 for the exact tree.)
- **Serialization (deviation from plan §1.1, approved 2026-06-22):** use **plain immutable Dart classes with hand-written `fromJson`/`toJson`** and **plain hand-written Riverpod providers** — **no `freezed`/`json_serializable`/`riverpod_generator`/`build_runner` codegen**. Rationale: removes the codegen toolchain's version-conflict + regen-friction risk under Flutter 3.41 (2026), keeps models explicit/debuggable, same architectural intent. Models are `const`, `@immutable`, with `copyWith` where needed. Map snake_case → the exact camelCase the plan specifies (e.g. `is_registration_completed`, and the separate top-level `needs_registration`/`is_new` flags — don't collapse them). *If you ever want strict freezed instead, this is the one place to revert.*
- **i18n:** `flutter gen-l10n` with `app_ar.arb` (primary, RTL) + `app_en.arb`. **Extract hardcoded Arabic strings per-screen as each is wired** (not big-bang). Every new user-facing string goes into **both** arb files.
- **Shared state widgets** (build in P1, use everywhere): `LoadingState`, `ErrorState` (with retry), `EmptyState`, `OfflineState`, `PaginatedListView`, `AppChip`, `GovernoratePicker`, plus the cross-cutting `ClubPicker`/`TeamPicker`.

## 5. Per-screen conventions checklist (apply to every screen you wire)

- [ ] Data fetched through `core` `ApiClient` only — never raw Dio in a widget.
- [ ] Wrapped in Riverpod `AsyncValue`; renders `LoadingState` / `ErrorState`(+retry) / `EmptyState` / `OfflineState`.
- [ ] Paginated lists use the shared `PaginatedListView` (reads `meta.pagination`, `hasMore`).
- [ ] Every image path passes through `assetUrl(...)`.
- [ ] `Accept-Language` rides automatically (interceptor); **writes** send raw `_ar/_en`.
- [ ] 422 `errors` mapped to fields; `message` shown for 403/404/business-422; 429 backed off.
- [ ] New strings added to **both** `app_ar.arb` and `app_en.arb` — never hardcode new copy.
- [ ] Reused the clay kit + theme tokens; no new visual primitives.
- [ ] Role UI gated by **probing** the manage-* endpoint (200 vs 403), not the role string alone.
- [ ] Inert data (scores, phone numbers, dates) forced `TextDirection.ltr` where the original did.

## 6. Definition of Done (every phase must hit all of these)

A phase is **green** only when: screens wired to live endpoints · models + providers + routes in place · loading/error/empty/offline states present · i18n keys added for new strings · `flutter analyze` clean · `build_runner` regenerated · a **manual acceptance pass against seeded demo data** matches the plan's "Acceptance" line for that phase. No placeholder data remains for shipped features.

## 7. Hard "never do this" list

- ❌ Never restyle, re-space, recolor, or re-lay-out an existing screen/widget to "improve" it.
- ❌ Never edit `lib/theme/*` or the clay widgets' visual output without explicit approval.
- ❌ Never introduce a second design language, font, or color outside `AppColors`/`AppText`/`Clay`.
- ❌ Never call Dio from a widget; never bypass the envelope unwrap / `assetUrl` / `AsyncValue` patterns.
- ❌ Never leave `picsum.photos`, `TODO(content)`, or fake `static const` data in a wired screen.
- ❌ Never assume a role from `roles[]` alone for manage-* screens — probe the endpoint.
- ❌ Never hardcode the base URL in code — only `Env`. Never send both `_ar/_en` on reads, never send raw localized fields on reads, never forget them on writes.
- ❌ Never skip a phase's manual acceptance pass or start a phase whose Open Decision is unresolved.
