The IQS backend is being built from the spec in `laravel_backend_plan_update.md` (9 phases). The user authorized **installing all plan Composer packages** and to **build straight through the phases** (1 → 2 → 6 → 3 → 4 → 5 → 7 → 8 → 9), only pausing at real blockers. Two surfaces share one Laravel 12 app: the Flutter **mobile API** (`/api/v1/*`, Sanctum token, `users` table) and the **admin JSON API** (`/admin/api/v1/*`, session/`web` guard, `admins` table) consumed by the Vue SPA in `resources/js/admin/`.

**Why:** large multi-phase greenfield build; the user wants both surfaces progressing together and minimal check-ins.

**How to apply:** continue to the next unbuilt phase without re-asking for scope/package approval. Each phase ends green: migrations + seeders + endpoints + feature tests + `vendor/bin/pint --dirty`. Keep the §0.5 envelope (`App\Support\ApiResponse`), dual-guard separation, and `*_ar`/`*_en` localization conventions.
